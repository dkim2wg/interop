# dkim2.com Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild dkim2.com as linked static pages built around the "shrink the grey area" argument, with a Deployments page generated from one JSON file per service / software product.

**Architecture:** Plain static HTML under `deploy/www/`, one shared `style.css`, a hand-copied nav on every page, diagrams as HTML + CSS `<figure>`s. `/deployments/index.html` is generated by a core-Perl script from `deployments/sites/*.json` + `deployments/software/*.json` and a template, run by `deploy.sh` straight into the web root.

**Tech Stack:** HTML/CSS, Perl 5 core modules only (`JSON::PP`, `File::Temp`, `Getopt::Long`), `prove`, nginx `try_files $uri $uri/`.

**Spec:** `docs/superpowers/specs/2026-11-13-website-split-design.md`

## Global Constraints

- Nav, exact order and hrefs, on every page:
  `<nav class="site"><a href="/">Home</a> <a href="/how/">How it works</a> <a href="/get-ready/">Get ready</a> <a href="/try/">Try it</a> <a href="/implementations/">Implementations</a> <a href="/deployments/">Deployments</a> <a href="/validate/">Validate</a> <a href="/verify/">Verify</a></nav>` — current page's link has `aria-current="page"`.
- Subpages link `/style.css` (absolute). Same footer everywhere.
- Definition of good, verbatim on Home: "**Good** means: from who it says it's from, with every change attributable to whoever made it."
- From rule, verbatim in `/how/#changes`: "A hop that makes significant changes becomes the message's author, and must put its own From on it." followed by "(Proposed for the next draft; not yet in the specification.)"
- No mention of `canmodify` / `draft-clayton-dkim-canmodify` anywhere on the site; no Topicbox example.
- Reflector / originate / bounces / implementations text moved verbatim (except the listed table updates).
- Old anchor ids preserved: `originate`, `bounces`, `reflector-signing`, `reflector-brand`, `reflector-brand-nd` (on `/try/`), `other-implementations` (on `/implementations/`).
- Deployment entry keys exactly `name, url, kind, signs, verifies, since, notes, source`; required `name, url, kind, signs, verifies`; `since` `YYYY-MM`; `url`/`source` https only; filename `[a-z0-9-]+\.json`.
- No client-side JS except the old-anchor redirect on `/`.

## Review Focus

- Entry text containing `<`, `&` or `"` (e.g. `1&1`) — escaped, never raw markup (Task 4 test `escapes_html`).
- `url`/`source` not `https://…` (e.g. `javascript:`) — rejected naming the file (Task 4 `rejects_*`).
- Editor/OS junk in the data dirs (`notes.txt`, `x.json~`, `.DS_Store`) ignored; `.json` with a bad name rejected (Task 4 `ignores_non_json`, `rejects_bad_filename`).
- Diagrams on a 400px-wide phone — bars keep labels legible, cards stack; checked by a narrow-viewport screenshot in Tasks 2 and 3.
- Any internal link or `#fragment` left pointing at content that moved — `deploy/t/www-links.t` covers every page incl. the deployments template (Task 1, extended as pages land).
