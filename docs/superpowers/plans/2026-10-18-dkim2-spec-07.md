> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring every DKIM2 implementation (C, Python, Perl, Go, browser JS, Mailman, Sympa), the cross-implementation harnesses, the docs and the live box from draft -06 to draft -07.

**Architecture:** Each implementation is changed independently against one shared contract, so that all of them make identical choices. Tasks 1–5 run in parallel, in separate worktrees on branches `spec07-<impl>`. Task 6 (Mailman) is in another repo. Task 7 (Sympa) needs Task 4's Mail::DKIM2. **Tech Stack:** C/OpenSSL 3, Python 3.14 + cryptography, Perl 5 + CryptX, Go 1.26 stdlib only, ES modules + node:test, Mailman 3 (Python), Sympa 6.2 (Perl).

**Spec:** `docs/superpowers/specs/2026-10-18-dkim2-spec-07-design.md` (the contract, C1–C8). Its source is `spec/draft-ietf-dkim-dkim2-spec-07.txt`. The per-implementation findings, with file:line, are in `docs/superpowers/specs/2026-10-18-dkim2-spec-07-audit.md`. Read all three before starting a task.

## Global Constraints

- MLDSA44-Ed25519-SHA512 is out of scope (decision 1).
- Emit lowercase JSON keys; accept any case; a duplicate that differs only in case is "contains invalid JSON" (decision 2). Tag names: accept any case; a duplicate that differs only in case is "syntax error".
- Error strings are exactly as in contract C6, in the form `STATE: text`.
- Future-timestamp limit: 86400 s. Expiry: 1209600 s.
- Go keeps zero module dependencies.
- `DKIM2_DRAFT = ietf-dkim-dkim2-spec-07`, `DKIM2_DATE = 2026-10-18`; Perl `$VERSION = '0.23'`.
- History comments keep their version ("spec-05 narrowed ...", "draft-05 added sha512"). Do not edit `spec/*.txt`, `docs/superpowers/` (other than these three files), or `dkim2tests/`.
- Run focused tests while iterating. Run each implementation's full suite once at the end of its task. Run the cross-implementation matrices only in Task 8.
- Mailman: develop on `dkim2` (TDD). Backports to `dkim2-3.3.10` and `dkim2-3.3.8` are apply-cleanly plus one full run each, one branch at a time.
- Never push hm. Never upload to CPAN; Bron does both.

## Review Focus

- A From header folded over several lines, carrying an RFC 2047 display name and angle-addr (`=?utf-8?q?Caf=C3=A9?= <a@example.com>`), must parse as one mailbox and pass A1. Add it to A1 in every verifier.
- Postfix-style trailing-dot or uppercase domains (`<A@Example.COM.>`) in mf=/rt= must match `example.com`. Add to C1 in every verifier (i=1 rt with uppercase + trailing dot).
- An `nd=` signature as the top signature in signer-gate (outbound) mode, where the signer's own d= equals nd=, must still sign. Inbound verify of the same message must give `unexpected nd= tag`. Add both to each signer-gate suite.
- A message whose From changed in an *unsigned* top MI, signed by the gate with a matching D, must sign. With a non-matching D, it is refused with the A3 string. Add to each signer suite.
- A Recipe with valid UTF-8 non-ASCII in "d" (e.g. `"d":["naïve"]`) must still undo byte-exactly after the "b"→"u" change. U1 already covers this; also check the body-line variant in U2's test file.
